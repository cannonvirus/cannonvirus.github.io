코딩 에이전트가 한 작업을 오래 이어 가면서, 단계마다 모델에 다시 보내는 컨텍스트가 토큰 비용에서 차지하는 몫이 커졌다. [Cursor](https://cursor.com/blog/improved-token-efficiency)는 이 비용을 줄이려고 에이전트 하네스(harness)를 고쳤다. 하네스는 모델에 보낼 요청을 조립하는 소프트웨어다. 컨텍스트를 어떻게 재사용할지, 작업을 언제 여러 에이전트에 나눌지도 하네스가 정한다. 몇 달에 걸쳐 바꾼 결과, 에이전트 품질은 낮아지지 않았고 사용자의 토큰 비용은 7% 줄었다.

```요약
요약: Cursor는 시스템 프롬프트, 도구 정의, 캐시 배치, 파일 읽기, 하위 에이전트 사용을 고쳐 에이전트 품질을 유지한 채 사용자 토큰 비용을 7% 줄였다.
```

```용어
하네스(harness): 모델 바깥에서 요청을 조립하고 컨텍스트 재사용과 작업 분담을 정하는 에이전트 실행 소프트웨어다.
정적 컨텍스트: 매 요청에 처음부터 들어가는 내용이다. 필요할 때만 불러오는 내용은 동적 컨텍스트라고 부른다.
캐시 중단점(breakpoint): 요청의 어디까지를 재사용할 앞부분으로 볼지 클라이언트가 직접 표시하는 위치다.
콜드 캐시 미스(cold cache miss): 재사용할 캐시가 없어 요청을 처음부터 처리해야 하는 경우다.
하위 에이전트(subagent): 상위 에이전트가 일을 맡기는 별도 에이전트로, 보통 새 컨텍스트 창에서 시작한다.
```

## 1. 시스템 프롬프트를 줄인 배경

시스템 프롬프트는 대화 내내 매 턴에 들어가서, Cursor가 직접 통제할 수 있는 비용 가운데 가장 큰 편이었다. 모델 성능이 낮던 때에는 도구 사용법과 작업 절차를 일일이 적어야 했다. 긴 해시 출력이나 이모지 같은 이상 행동을 막는 지시도 필요했다.

모델이 나아지면서 이런 지시는 대부분 필요 없어졌고, Cursor는 시스템 프롬프트의 약 66%를 덜어 냈다. "반드시", "절대 하지 말 것" 같은 지시를 늘어놓지 않고 도구의 동작만 정의해도 모델은 대체로 따랐다. 어느 모델 계열에서나 결과는 같았다.

Cursor는 지시를 고칠 때 평가보다 대규모 사용자 A/B 테스트를 중시한다고 밝혔다. 평가는 빨리 돌릴 수 있는 대리 지표이지만 어려운 문제 위주로 짜여 있어서 실제 사용자 요청의 분포와 다르기 때문이다.

## 2. 필요할 때만 불러오는 도구 정의

도구 정의도 매 턴 들어가는 컨텍스트인데, 올해 백그라운드 셸 감시와 클라우드 하위 에이전트 같은 기능이 붙으면서 크게 불어났다. 반면 도구 하나하나가 쓰이는 대화는 전체의 20%에 못 미쳤다.

이에 Cursor는 올해 초 MCP(Model Context Protocol) 도구에 쓴 방법을 내장 도구로 넓혔다. 당시 MCP 도구를 동적 컨텍스트로 옮겨 필요할 때만 불러오게 하자, MCP 도구를 호출한 세션에서 전체 토큰이 46.9% 줄었다.

어떤 도구를 정적 컨텍스트에 남길지는 A/B 테스트로 정했다. Cursor는 사용 빈도와 모델이 처음부터 그 도구를 봐야 하는지를 기준으로 여러 구성을 시험했고, 토큰 사용량과 지연 시간, 도구 호출 오류로 품질을 확인했다. 그 결과 읽기, 검색, 편집, 셸 도구가 남았다. 일부 모델이 호출을 지어내곤 하던 `ask_question`과 Plan Mode에 필요한 `create_plan`도 남겼고, 나머지 도구는 에이전트가 필요할 때 불러온다.

## 3. 캐시 중단점과 요청 앞부분 정리

에이전트는 턴마다 도구, 시스템 지시, 설정, 지금까지의 대화를 담은 긴 요청을 다시 보낸다. 앞부분은 거의 그대로이고 끝의 대화만 늘어나므로, 모델 제공사는 프롬프트 캐싱으로 바뀌지 않은 앞부분을 재사용한다. 다만 GPT-5.6 이전에는 최신 요청을 기준으로 캐시 경계가 자동으로 정해졌다. 이 때문에 거의 바뀌지 않는 도구와 시스템 지시도 그것만 따로 재사용 대상으로 표시되지는 않았다.

GPT-5.6부터 OpenAI API는 기본 암묵적 캐싱과 함께 명시적 캐시 중단점(breakpoint)을 지원한다. Cursor는 이 기능으로 고정된 층 뒤, 늘어나는 대화 앞에 중단점을 두었다. 다음 그림에서 파란 칸은 고정된 층, 주황 칸은 늘어나거나 바뀌는 층, 점선 칸은 중단점이다. 오른쪽 구성에서도 최신 메시지에 생기는 암묵적 중단점은 그대로 남는다.

![GPT-5.6 이전과 명시적 캐시 중단점 도입 후의 요청 구성 비교 (출처: cursor.com/blog/improved-token-efficiency)](photos/0f19d35992dd.webp "GPT-5.6 이전과 명시적 캐시 중단점 도입 후의 요청 구성 비교 (출처: cursor.com/blog/improved-token-efficiency)")

중단점은 앞부분이 고정되어 있어야 효과가 있으므로, Cursor는 도구와 시스템 지시 자리에 거의 바뀌지 않는 내용만 남겼다. 스킬, 하위 에이전트, 환경 정보처럼 사용자와 요청마다 달라지는 설정은 캐시 경계 뒤의 '팬텀 사용자 메시지(phantom user message)'로 옮겼다. 그 결과 콜드 캐시 미스(cold cache miss) 비율이 20% 줄었다.

## 4. 파일 읽기: 줄 번호 간격 조정

에이전트가 작업하면서 더하는 컨텍스트 가운데 큰 몫이 파일 읽기에서 나온다. Cursor의 `Read` 도구는 그동안 모든 줄에 번호를 붙였다. 모델은 줄을 스스로 잘 세지 못하는데, 사용자에게는 특정 구간을 짚어 줘야 하기 때문이다. 번호 하나는 3~5토큰 정도지만, 한 세션에서 수만 줄을 읽으면 그 양이 무시하기 어려워진다.

그래서 Cursor는 10줄마다 한 줄에만 번호를 붙이도록 바꿨다. 이 간격으로도 모델은 코드를 제대로 인용했고, 품질 저하 없이 캐시 읽기 토큰이 1.6% 줄었다.

## 5. 하위 에이전트 사용과 모델 선택 규칙

하위 에이전트(subagent)에 일을 맡기면 토큰을 아낄 수 있지만 조율 비용이 따른다. 하위 에이전트는 상위 에이전트의 대화 전체를 이어받지 않고 보통 새 컨텍스트 창에서 시작한다. 결과를 보고받은 상위 에이전트도 그 작업 내역을 계속 지니지 않아도 된다. 반면 컨텍스트를 공유하지 않는 에이전트끼리는 같은 일을 하거나 이미 필요 없어진 일을 이어 갈 수 있다.

Cursor는 먼저 코드베이스 탐색에 하위 에이전트를 쓰라고 강하게 권하던 지시를 지웠다. 하위 에이전트가 학습 데이터와 사후 학습에 널리 들어가면서 모델이 이 방식을 이미 익혔기 때문이다. 지시를 지우자 하위 에이전트를 쓰는 빈도가 한쪽으로 치우치지 않게 되었다.

또 하위 에이전트가 쓸 모델을 고르는 조건을 좁혔다. Cursor에서는 어떤 모델로든 하위 에이전트를 띄울 수 있으므로 비싼 계획용 모델과 싼 구현용 모델을 짝지을 수도 있다. Cursor는 도구 인자를 바꿔, 사용자나 하네스가 지시할 때만 에이전트가 다른 모델을 고르게 했다.

Cursor는 이렇게 하네스를 고쳐 품질을 유지하면서 토큰 비용을 7% 줄였다. 앞으로도 긴 실행에서 컨텍스트가 쌓이는 방식을 측정하고 반복 처리를 줄일 곳을 시험할 계획이며, 그러면 토큰 사용량이 에이전트의 작업량보다 훨씬 느리게 늘 것으로 내다봤다. 같은 경험은 Grok Bot의 하네스를 최적화하는 데에도 쓰고 있다.
